# JAZU Desktop

Independent Electron desktop; it never imports or starts the personal server.

From the checkout root, run `npm --prefix app ci`, then `node src/main.ts app` (`--kiosk` for fullscreen). The CLI builds the desktop and serves the site's static output on a random loopback port. Closing the app stops that server. To use an already running local site: `JAZU_APP_URL=http://localhost:8080/desk npm --prefix app start`.

The sandboxed renderer has no Node integration. Its isolated preload relays only the existing `jazu-host` message envelope; the main process accepts messages only from the pinned top-level localhost frame. Native host sessions use the same framing, validation and PTY implementation as the extension (`shared/host/`). Linux requires Python 3 or util-linux `script`. Navigation to another origin is blocked; new links open externally. Reloading closes native terminals.

On `/desk`, Files mounts the native filesystem using the same bounded channel as the personal server. Open and save work in normal editor/folder windows. `JAZU_APP_ROOT` optionally confines this view to an existing absolute directory; the default is `/` on Linux and the home drive on Windows. Paths inside the desk are relative to that root. Leaving `/desk` restores the browser filesystem, and reload ends native terminals.

Files → **This computer** offers clipboard read/write, system volume/mute, native-window discovery, focus, close and placement by screen coordinates. Linux window adapters use `i3-msg`, `swaymsg`, `hyprctl`, or `wmctrl` for other EWMH X11 managers. Native application size hints may round requested dimensions. Audio uses PipeWire/WirePlumber's `wpctl`. X11 key combinations use `xdotool`; Wayland global injection is explicitly unavailable. Missing system commands produce visible errors. Browser media still uses normal browser controls and permissions.

The desktop never exposes a shell-command RPC. Requests use validated operations, bounded numbers and base64 chunks; OS tools receive separate argument vectors. Only the pinned top-level localhost document may invoke them. Native window controls do not yet project every graphical application into the desk's split/layout graph, and full system audio capture plus compositor-independent Wayland input remain open. Windows has no native PTY backend.

Validation: root and app TypeScript checks, package build, root import boundaries and host protocol regressions pass. `npm run test:app` launches real Electron and verifies the desk loads, Node integration is absent, the preload handshake works and external navigation is blocked. Both compiled native PTY backends passed on the ARM64 personal server from a temporary directory, removed afterwards; no running service was changed. The host OS has Node 20, so direct TypeScript host scripts need a newer Node or a compiled runtime.

Clipboard tests preserve the prior clipboard. Root/app types and filesystem/protocol regressions pass.
