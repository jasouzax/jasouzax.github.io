# Jazu Components
**Jazu** *(JAsouZa User interface)* is my personal project whos objectives are to develop a website system that serves my (owner) Portfolio (Centralized area for recruiters and general public from navigating my works), my Workspace (The interface for me to do my personal projects, works with clients, etc.), and my Showcase (The system itself implements several actual technical techniques of specific fields to actually demonstrate my capabilities live). The system can be broken down into these components:

1. **Content Management System (CMS)** - To help create and maintain a huge website, the system generates/updates the complete static website following Incremental Static Regeneration (ISR) from easy to modify files.
    1. **Content** `{codebase}/content` - All of the website's content are stored at `{codebase}/content`. Since the owner as fully control over this region there isnt any fixed structure here, so the engine scans every file and identifies how to interpret it to the final website. This freedom of control is so effective that basically if you put all XML into a single XML file, there wouldnt be any difference aside from the relative paths to the page's resources changing (You can put a huge media, and it wont be in the final static website unless its it referenced by a XML file).
        1. **Pages** - Pages are represented as XML files as its easier to represent object/entity. They are defined by a `<page>` tag *(Has stated in 1.1, a single XML can have multiple of these tag, normally its the same page but just different language)*, their attributes are `path` of the page like `path="/"`, the `name` and `icon` of the page used in head navigation, `rank` of the page used in head navigation's order, and `info` for the page's description metadata. The page can have the following children tags:
            1. **Hero** `<hero>` - This provides quick and direct information usually used in landing pages, contact me sections, sitemaps, and error pages. Its attributes are the `status` which is a small detail on status (usually in the landing page to show the status of the develop if available to for new project), `name` of the hero (In landing page its the owners's name, and in others just a header to represent the contact me section, error section, etc.), `tags` of the hero (In landing pages its the roles of the owner), and `info` which is a description of the hero. The possible children are:
                1. **Item** `<item>` - Represents in a list of links shown in the hero component which can be used to represent contain informations, webpages, etc. Each item has attributes `icon`, `name`, `text`, and `link` of that item with an optional `print` to show when on print mode.
                2. **Action** `<action>` - Represents the available actions show in the hero component which can be used to highlight important pages, actions to take, etc. Each action has attributes `icon` and `text` shown in the button, with `link` to the action, and optional attribute `primary` to suggest primarly highlighting.
            2. **Expertise** `<expertise>` - This provides the complete navigation to browse the owner's experience, education, projects, certifications, competitions, etc. Its contents are automatically determined by the whole website's contents, grouping project pages `<event>` and `<project>`. It has no attributes. Its interface includes:
                1. **Skill Head** - The top of the expertise is a tab head with options to browse specific skills, which updates the whole expertise with that skill specifically so recruiters have an instanteous option to view what skills specifically they are interested at.
                2. **Search** - The ability to search the expertise by text, this shows results matching the text regardless what skill is focused on.
                3. **Timeline** - The expertise are shown in this timeline, allowing users to preview the timeline of projects or experience.
                4. **Slideshow** - A slideshow showcasing the event/project directly, it has filter tags on top to filter the slides, button to view all projects, the slide on the center, and slide navigation on bottom.

The desk's attributes includes the `icon`, `name`, and `info` of the Desktop. The two components are:

    2. **Engine** `{codebase}/src` - This directory contains the source file needed to run the engine or the infastructure, here `{codebase}/src/main.ts` is the main script with access to NodeJS access points but since the rest of the codebase is just general Typescript then when switching between frameworks like DenoJS or etc, then only `main.ts` or typescripts in this directory needs changing. The `main.ts` is just a wrapper/cli to access the engine either to build, check, serve, etc.
        1. **Web App Methods** `{codebase}/src/web` - This folder contains the scripts responsible for generating the pages, it uses TSX with a custom JSX factory to turn the the elements into HTML strings. Each element represents a component like `<page>`, `<expertise>`, etc. It implements the following methods or priorities:
            1. **Accessibility** - Website is navigatable no matter what device, such as WCAG, Keyboard/Remote/Mouse only navigation, etc.
            2. **Compatibility** - Website can be used anywhere from modern browsers, legacy and depricated browsers, browsers without JS support (like TOR), etc.
            3. **Multi-Theme Support** - Multiple web themes can be implemented in the same webpage to showcase user interface designs and native preference support. This can be done by just switching the CSS and JS, the DOM is the same meaning the DOM's identification and classes are theme ambigue so in some themes some DOM are hidden or used, no DOM is created just for a theme.
            4. **Custom Font for Text and Icons** - Fonts are also generated in this system as they can easily change the text font and also icons encompassing the Private Use Areas (PUA) unicode as different themes might require different text and icon fonts by just changing the font file instead of requiring SVG generation through JS or similar.
            5. **CSSOM Optimizations** - The style sheets are CSSOM Optimized has they implement Block/Element/Modifier (BEM) like naming convention and make sure most selectors run at O(1). This includes state handling where the parent's has or where uses ID so its state check is O(1).
            6. **No JS Navigation** - The website can be used without JS as CSS uses states held by input elements to determine dynamic styling, only truely dynamic behavior is disabled when JS is disabled like using Desktop Actions.
            7. **SEO Accounted** - All SEO capabilities are taken into account like the Open Graph Tags, Search Engine, Sitemap, robots, llm.txt, etc. even the legacy ones like meta keyword, and the native decorative ones like the browser head color on mobiles, etc.
            8. **Single Page App (SPA)** -  The initial page loads already has the page content rendered client side, but everytime a new page is to be loaded the hyperlink/form's is intercepted by the script and is canceled default (this way right click to new tab still works), here the website makes a request to the website's JSON version where the client then renders the page.
            9. **Progressive Web App (PWA)** - The website can be downloaded as a web app allow better showcase on ability to PWA with native features and offline capabilities.
        2. **Cloud/IoT** `{codebase}/src/node` - This folder contains the scripts used (after compiling typescript to javascript) in the cloud nodes such as the cloudflare server's pages and workers, the personal server, etc. The following features are implemented:
            1. **Static Hosting** - The website's static content like webpages, styles, script, etc. are generated before hand and hosted without needing to maintain a server like using Cloudflare Pages, ensuring that if our servers went offline the website still functioning and not down.
            2. **Dynamic Routing** - The website implementes a worker router over the static hosting to ensure that the website gains multiple abilities instead of just just to static hosting. For instance it can redirect "/api/{name}" to the corresponding data/iot server, and even dynamic pages whos doesnt follow the website's template or whos dynamic content is needed in the SEO and is not client/user dependent, can be routed to another server.
            3. **API Forwarding** - The subdirectories of "/api" all returns JSON code even if they could be routed responses of different servers. The API path is `/api/{version}/{resource}/{id}/{subresource}?{query}` like `/api/v1/users/123/orders?status=shipped&sort=desc`, note that resource name is plural and query not used to identify specfic resources. The central router keeps a track of APIs and their respective server such that I can add new APIs without disruption on current APIs.
            4. **Personal Server** - The personal server runs the `main.ts` which aside from providing live build and push to cloudflare pages, is also the repository hub of `/projects` and `/work` both public and private which through cloudflare router and zero trust to allow the website to act as a git site meaning anyone could `git clone jasouza.com/projects/calculator` unless that project is private, and so my clients could git push to their repositroy at `/work` or my parterns could collaborate on `/projects`. Since it stores the repositories it also implements my custom Continuous Integration and Delivery (CI/CD) and AI Agents to have complete development capability. This is all also available through the interface `<desk>` where the repository's file is visible in the `file` tab, and the agent communication is visibile in the `agent` tab, and the git timeline is visible in the `git` tab. This server however uses ElectronJS for virtual browser purposes.
        3. **Desk** `{codebase}/src/desk` - This folder contains scripts to compile GNU (linux) or Windows applications into WASMs to be used by `<desk>`, its the only codebase not strictly defined to be typescript as it can be Bash for linux or Batch for windows.
    3. **Output** `{codebase}/dist` - This is the final generated website that can be hosted directly to cloudflare pages. Its all static and is the root host directory.
2. **Cloudflare Services** - The cloudflare domain is `jasouza.com` and so most of the web services are also cloudflare.
    1. **Sub Domain** - Subdomains are capped at 2 levels (*.jasouza.com) because cloudflare's free SSL doesnt include above 2 levels so we use a minus technique to bypass it like `*-demo.jasouza.com`, etc.
        1. **Demo** - Demo Minimum Viable Product (MVP) for the purpose of presentation/showcase are demonstrated in the `*-demo.jasouza.com` and are also configurable by the central router so that I can configure which demo goes to switch server.
        2. **Client** - Websites I want to showcase to my clients goes to `*-work.jasouza.com` which is specifically hosted in my personal server as the option to host them to begin with are in the `/work` page settings.
        3. **Project/Apps** - Apps/Projects are also identified at `app.jasouza.com` which just redirects to `jasouza.com/projects/app` because having two duplicate path for both paths flags SEO bots as redunant of spam.
    2. **EMail** - Emails are directed to an actual gmail address, this helps secure protection incase of a spam attack or etc. Like `jason@jasouza.com` redirects to my work email.
    3. **Services** - Cloudflare pages is used to host the static files except for media, while the media or heavy files are stored with Cloudflare storage, while client's messages, quotations, etc. are stored in Cloudflare database, while the personal server access to passthrough the centralized git repository with CI/CD uses cloudflare zero trust so that git can clone and push to the `jasouza.com` domaina and even be possible to ssh to the domain, and finally Cloudflare Worker to ocastrate the whole system routing `*.jasouza.com/*` so that it applies to all of the domain and subdomain, where unassigned subdomain just shows the normal empty page
