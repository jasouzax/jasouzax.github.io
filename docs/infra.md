# Infrastructure

Everything outside the TypeScript source that provisions or emulates the cloud. Operational *steps* are in the root [README](../README.md) (Local Use, Host Use, Server Use); this page explains what exists. Code that runs on the nodes: [src/node.md](src/node.md). Status: [feat/cloud.md](feat/cloud.md).

## Architecture

```
visitor ──► Cloudflare ──► Worker (router)  ──► Pages            static dist/ (HTML, JSON, CSS, JS, small media)
                           │   │    │
                           │   │    └──► R2 (ASSETS)              large media, WASM (range requests)
                           │   └──► KV (REGISTRY)                 host:<name>-demo / -work → external HTTPS origin
                           │        D1 (DB)                       client schema (APIs not enabled yet)
                           └──► Tunnel + Access (service token) ─► personal node (127.0.0.1:8788, signed Git reads)
```

The public site is static and keeps working if the personal node is offline.

## Terraform (`terraform/`)

Staging is a separate Terraform root at [`terraform/staging`](../terraform/staging/README.md), with its own state and Cloudflare provider lock. `npm run tf:staging -- plan` / `apply` bundle its Worker and automate Pages, R2, Worker secrets, Pages domain association, DNS and routing without loading production state. See [post-merge setup](infra-staging.md). The production root described below retains its existing ownership and import requirements.

| Resource | Purpose |
|---|---|
| `cloudflare_r2_bucket.assets` | Large media and WASM (`jazu-assets`) |
| `cloudflare_workers_kv_namespace.registry` | Demo/work subdomain registry (`jazu-registry`) |
| `cloudflare_d1_database.db` | Database (`jazu`) |
| `cloudflare_pages_project.site` | Pages project (name from `config.json.deploy.pages_project`); content uploaded by `deploy` |
| `aws_s3_object.large_assets` | Uploads files >25 MiB to R2 through the S3 API (the Cloudflare provider has no R2 object resource) |
| `cloudflare_workers_script.router` | The bundled Worker with bindings `ASSETS`, `REGISTRY`, `DB`, vars `DOMAIN`, `PAGES_ORIGIN`, `PUBLIC_PROJECTS`, optional `PERSONAL_ORIGIN`, optional secrets |
| `cloudflare_workers_script_subdomain.router` | `workers.dev` subdomain (`workers_dev`, default on) |
| `cloudflare_workers_route.router` | Routes `{domain}/*` and `*.{domain}/*` |
| `terraform_data.d1_migrations` | Runs `node src/node/d1_migrate.ts` when the DB or any migration changes |

Files: `versions.tf` (providers `cloudflare ~> 5.0`, `aws ~> 5.0` for R2, **local state by default**), `variables.tf`, `main.tf`, `outputs.tf` (`pages_origin`, `assets_bucket`, `kv_namespace_id`, `d1_database_id`), `terraform.tfvars.example`.

Variable sources: `TF_VAR_*` from `.env`, or `terraform/terraform.tfvars` (ignored). Variables generated by `deploy` (`worker_name`, `pages_project`, `domain`, `public_projects`, `personal_origin`, `worker_bundle`, `large_assets`) arrive through `.cache/deploy/<stamp>/deploy.auto.tfvars.json`; pass it with `-var-file`.

**Things Terraform does not do:** DNS records for the apex/wildcard, Cloudflare Access applications/Tunnels, Email Routing, analytics. Create them in the dashboard (or extend the module). Deleting removed R2 objects is an owner retention task.

**State** contains secrets and is local; for more than one deploy machine configure a remote backend in `versions.tf` (for example R2 via the `s3` backend). Never commit state or tfvars.

`npm run tf:fmt`, `npm run tf:validate` (init with `-backend=false` + validate; needs the providers to download).

## Local cloud emulation (`wrangler.local.jsonc`)

Synthetic bindings for `wrangler dev`: `DOMAIN=localhost`, `PAGES_ORIGIN=http://127.0.0.1:8080`, `PUBLIC_PROJECTS=[]`, D1 `DB` (`jazu-local`, `migrations_dir=migrations`), R2 `ASSETS` (`jazu-local-assets`), KV `REGISTRY`. Data lives in the ignored `.wrangler/`. **Never deploy this config.**

Scripts: `npm run db:local` (apply migrations locally), `npm run cloud:dev` (`wrangler dev --config wrangler.local.jsonc`, Worker on :8787).

## D1 schema (`migrations/0001_work.sql`)

`clients` (uuid **hash**, slug, Google subject), `device_sessions` (hashed token), `files`, `messages` (idempotency unique per client, soft delete, kinds `text|file|dashboard|receipt|pin`), `receipts` (minor units, `paid|pending`), `pins` (tenant-consistent foreign keys), `dashboards`, `desk_state` (versioned), `admin_audit`. Timestamps are Unix seconds; ids are sortable ULIDs. The schema exists; **no endpoint uses it yet**.

## Secrets and configuration map

| Value | Where it lives | Used by |
|---|---|---|
| `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID` | `.env` / shell | Terraform provider, D1 migrate, wrangler Pages upload |
| `TF_VAR_account_id`, `TF_VAR_zone_id`, `TF_VAR_r2_access_key_id`, `TF_VAR_r2_secret_access_key` | `.env` or `terraform.tfvars` | Terraform |
| `ORIGIN_HMAC_SECRET`, `ACCESS_CLIENT_ID`, `ACCESS_CLIENT_SECRET` | `.env` | Personal node (HMAC); pushed to the Worker as secrets by `deploy` |
| `JAZU_REPOSITORIES_JSON` | `.env` on the personal server | Personal node |
| `config.json.personal_server` | Repo (not secret) | Worker's `PERSONAL_ORIGIN` |
| KV `host:*` | Cloudflare KV | Worker subdomain proxy |

`.env`, `.env.*` (except `.env.example`), `.dev.vars*`, `*.tfstate`, `terraform.tfvars` are git-ignored.
